# Протокол MAIN ↔ DISPLAY

Этот документ содержит только то, что было подтверждено в ходе практического реверса конкретной сплит-системы `MSAFA-09HRN1-QC2`.

## Физический уровень

Обмен идёт по двум отдельным однонаправленным линиям:

- BLUE: `MAIN → DISPLAY`;
- YELLOW: `DISPLAY → MAIN`.

Скорость — **2400 baud**.

YELLOW стабильно читается как UART **8N1**. Для BLUE обычный UART ESP32-C3 оказался ненадёжным, поэтому в рабочем конфиге реализован RMT + программный декодер с параметрами, подобранными по реальному сигналу.

## Формат кадров

В обмене встречаются кадры с заголовками `0x55` и `0xAA`, PID `0x90` / `0x91`, полем длины, payload и контрольной суммой.

Проверенная контрольная сумма — сумма всех байт кадра по модулю 256.

## Периодический кадр YELLOW

В OFF и во время работы регулярно наблюдается:

```text
AA 90 08 00 00 20 00 00 00 00 00 9E
```

Он не является обычной пользовательской командой Coolix и используется дисплеем как служебный обмен с MAIN.

## Компактные 11-байтные команды

### Display / Sound toggle

```text
AA 91 07 B5 4A F5 0A A5 5A 00 C1
```

Соответствует Coolix:

```text
B5 F5 A5
```

Пары `B5/4A`, `F5/0A`, `A5/5A` являются байтом и его инверсией.

Это **toggle**, а не абсолютное состояние. Одинаковый пакет используется и для включения, и для выключения режима Display/Sound.

### OFF

Coolix OFF:

```text
B2 7B E0
```

В YELLOW наблюдался компактный сервисный кадр соответствующего семейства; рабочий парсер также распознаёт OFF по декодированному Coolix-коду `0xB27BE0`.

### FAN_ONLY MEDIUM

```text
AA 91 07 B2 4D 5F A0 E4 1B 00 C1
```

Coolix:

```text
B2 5F E4
```

### FAN_ONLY LOW

```text
AA 91 07 B2 4D 9F 60 E4 1B 00 C1
```

Coolix:

```text
B2 9F E4
```

### FAN_ONLY HIGH

```text
AA 91 07 B2 4D 3F C0 E4 1B 00 C1
```

Coolix:

```text
B2 3F E4
```

## Проверенные Coolix-коды

| Функция | Код |
|---|---|
| OFF | `0xB27BE0` |
| Swing | `0xB26BE0` |
| Display / Sound toggle | `0xB5F5A5` |
| FAN_ONLY AUTO | `0xB2BFE4` |
| FAN_ONLY LOW | `0xB29FE4` |
| FAN_ONLY MEDIUM | `0xB25FE4` |
| FAN_ONLY HIGH | `0xB23FE4` |

Режимы COOL/HEAT/DRY/AUTO и температура формируются стандартной ESPHome-компонентой `climate: platform: coolix`; обратное состояние дополнительно подтверждается по внутренней шине.

## Почему нельзя просто передавать в YELLOW через GPIO4

Текущий вход YELLOW построен через делитель:

```text
YELLOW → 47k → GPIO4 → 68k → GND
```

В RX-режиме это нормально. Но при попытке переключить GPIO4 в OUTPUT LOW ESP воздействует на YELLOW через **47 кОм**. Штатный передатчик DISPLAY удерживает линию достаточно жёстко, поэтому сформированный ESP сигнал искажается.

В эксперименте начало и/или середина отправляемого пакета менялись, и MAIN не принимал команду. Поэтому финальная схема использует GPIO4 только для чтения.

## Ограничение mute

Главный результат реверса: корректный пакет `B5F5A5` можно передать MAIN через штатную плату дисплея, но при настоящем OFF → ON первый писк всё равно возникает.

Были проверены варианты:

1. mute перед ON;
2. mute сразу после OFF;
3. mute + ON через штатный ИК-тракт;
4. прямой TX сервисного кадра по YELLOW.

Рабочая стратегия в финальном конфиге: сохранять пользовательское пожелание «Без звука» в ESPHome и **один раз** повторять `B5F5A5` после подтверждённого нового включения.

# Диагностика и восстановление

## После OTA кажется, что изменения не применились

Сначала посмотрите начало логов ESPHome. Важна строка:

```text
ESPHome version ... compiled on YYYY-MM-DD HH:MM:SS
```

Она должна соответствовать только что собранной прошивке. Если дата старая, новая OTA-сборка фактически не работает.

Проверьте наличие сообщений:

```text
OTA rollback detected!
The device reset before the boot was marked successful
Last reset was due to brownout
```

При таком сценарии ESPHome может откатиться на предыдущий OTA-раздел. Не отлаживайте поведение новой версии, пока не убедились, что она действительно загружена.

Успешный первый запуск подтверждается строкой:

```text
Boot seems successful; resetting boot loop counter
```

Если регулярно возникает `brownout`, проверьте питание ESP32-C3, качество контактов, 5V/3.3V питание и просадки при работе Wi‑Fi.

## `Без звука` после перезапуска Home Assistant

Для v1.5 ожидаемое поведение такое:

1. Включить `Без звука`.
2. Выполнить в Home Assistant жёлтый пункт **«Перезапуск Home Assistant»**, а не перезагрузку всей ОС.
3. После восстановления интеграции ESPHome switch должен оставаться ON.

Сам рестарт Home Assistant не должен отправлять `B5F5A5` физическому кондиционеру — ESP только повторно публикует сохранённое локальное состояние.

## Первый писк после полного OFF → ON

Это известное аппаратно-протокольное ограничение текущей ревизии. После полного включения остаётся один стартовый писк. После подтверждённого ON v1.5 повторно применяет `B5F5A5`, и дальнейшие команды работают без звука.

# v2.0.0-rc3 — включение последнего режима через Алису

## Зачем это нужно

Home Assistant по умолчанию реализует обычный `climate.turn_on` выбором первого поддерживаемого режима в порядке HEAT_COOL → HEAT → COOL. Поскольку этот кондиционер поддерживает HEAT_COOL/AUTO, фраза Алисе «включи сплит-систему» может включить AUTO вместо последнего рабочего режима.

Прошивка RC3 не подменяет AUTO и не пытается угадывать источник команды. Вместо этого она хранит `last_active_mode` и публикует отдельную кнопку **«Включить последний режим»**.

## Поведение RC3

- последний COOL → кнопка включает COOL, а правило RC2 ставит стартовые 25°C;
- последний HEAT → кнопка включает HEAT, стартовые 30°C;
- последний FAN_ONLY → возвращается FAN_ONLY, температура не меняется;
- последний DRY → возвращается DRY;
- последний AUTO / HEAT_COOL → возвращается AUTO;
- OFF память режима не стирает;
- штатный пульт тоже обновляет память через принятые полные AA91-команды.

## Yandex Smart Home

Для климатической сущности нужно переопределить только действие включения. Пример для второй системы:

```yaml
climate.wifi_air_conditioner_2_konditsioner:
  turn_on:
    action: button.press
    entity_id: button.wifi_air_conditioner_2_vkliuchit_poslednii_rezhim
  turn_off:
    action: climate.turn_off
    entity_id: climate.wifi_air_conditioner_2_konditsioner
```

Существующие `custom_toggles` (например, mute) остаются в том же блоке.

После прошивки проверь фактический entity_id кнопки в Home Assistant. Если HA создал другой slug, в конфиге Yandex нужно использовать именно его.
